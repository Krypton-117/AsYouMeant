# AYM README 逐段评估与修正方案

评估日期：2026-09-08。基线：`b33c6e4ddc8b682db06c485c470b957b62d89590`，产品 0.3.1。

本文是具体修正方案，不是 README 改写后的发布物。本轮仅新增本报告；不改变运行时、许可证、已发布 npm 包、README 或 GitHub 元数据。下文 README 行号均基于此基线，英文与中文章节起始行当前一致；后续编辑会使行号移动。

## 1. 评估范围与证据强度

已完整检查两份 README，并核对 `docs/TASK-MODES.md`、现有 DSH 分发与 Web 验证记录、README 交接文档、包清单、Codex/Claude/OpenCode 适配器、DSH 原生插件、Codex Hook、原生 Skill 指令、0.3.1 验证边界及 release check。

- **事实问题**：文字与本地实现或版本证据不一致，可定位到代码。
- **使用路径缺口**：命令可能正确，但读者无法从说明完成下一步，或被引向不必要的步骤。
- **编辑判断**：影响理解、选择和检索的内容组织问题，不等于已测得的搜索排名损失。
- **待验证项**：需要真实宿主、外部资料或用户测试，不能以建议代替验证。

没有本项目的搜索曝光、点击、引用率或关键词流量数据。本报告不声称某个标题能提升特定比例的排名，也不把 llms.txt、关键词密度或 README 行数当作搜索引擎要求。外部论文与竞品描述本轮未重新核实，只评估它们在 README 中的位置与证据用途。

现状：每份 README 有 472 个内容行（按末尾换行 split 会得到 473 项）、34 个 Markdown 标题。安装章节从第 39 行开始，任务模式到第 149 行才出现，宿主汇总表到第 402 行才出现。没有显式目录。问题不是单纯“太长”，而是第一次选择产品需要的信息，被安装细节、历史说明和设计解释打断。

## 2. 上一轮粗评需要纠正的地方

1. README 第 17 行已经明确说到“过早开工、误解描述、添加未请求工作、检查不能证明结果”。不能再评价为“完全没有痛点表达”；真正的问题是这些表达没有继续成为适用场景、示例标题和独立回答段落。
2. 安装并非完全藏在底部，第 39 行已经开始。应修正的是“先统一构建，再选择宿主”的错误分流，以及源码路线压过了已验证的 DSH npm 路线。
3. 证据不是不存在：Claude 限制、DSH 精确版本、npm 与 Web 验证均已写出。问题是分散、语义层级不一致，首屏容易产生比证据更强的印象。
4. 首先不需要生成大量新网页。应先修复事实、建立单一安装入口和完整示例，再扩展独立问题页。否则只是把含混描述复制到更多地址。
5. 无法承诺“各种 AI 都搜到”。可验收的是页面能回答哪些问题、命令是否可运行、证据能否追溯；外部搜索曝光要单独实测。

## 4. 必须先修正的能力声明：不能只做营销改写

### 4.1 核心策略不等于原生宿主已完整观测

本地证据：

- `src/hosts/codex/adapter.ts:158` 将 `retry` 设为 null，下一行 `repeat` 也为 null。
- `src/hosts/claude/adapter.ts:97` 将 dependencyNames 设为空数组；107 行起 test、retry、repeat 为 null。
- `src/hosts/opencode/adapter.ts:113` 将 dependencyNames 设为空数组；123 行起 test、retry、repeat 为 null。
- `native/dsh/asyoumeant-dsh.js:178` 起按模式分流；199 行检查 allowedTools。它没有在此路径执行完整的核心重试和节点验收策略。

这些证据不表示所有相关动作都能绕过限制：某些动作可能因未知工具、无许可或其他策略先被拒。它们证明的是，不能声称每个宿主已准确识别“这是第几次重试”“这个测试有没有消费者”“这一项依赖是否获得批准”。

**首屏替代句（拟稿）**：

> AYM 帮助编程 Agent 在动手前明确需求和授权范围，并在支持的宿主工具路径上检查实施许可与动作权限。治理需要用户显式启用；具体可强制检查的内容取决于宿主适配。

**英文拟稿**：

> AsYouMeant (AYM) helps coding agents clarify requirements and approved scope before implementation. Its host integrations check implementation permits and action permissions on supported tool paths. Governance is opt-in; enforcement coverage varies by host.

详细能力表应有三列：核心策略能力、宿主提供的字段/事件、当前验证证据。字段缺失时写“未验证/未完整映射”，不能只放一个勾。完整映射属于另外的实现任务，不应在 README 修正文案时偷偷扩展代码。

### 4.2 “普通模式不治理”与控制状态故障要区分

`native/codex/hooks/asyoumeant-codex.cjs:48` 在普通模式直接返回；但52行起的异常处理会在无法读取模式/合同状态时输出拒绝。这是正常路径与错误路径的区别。

README 主文仍可写“普通模式不启用 AYM 门禁”，FAQ 应补：若插件无法读取自身状态，可能出现明确错误；不要把这种故障解释成“用户忘了 major-loop permit”。链接宿主排障说明，不在首屏堆底层错误码。故障行为是否要进一步优化属于独立实现议题。

### 4.3 pre-loop 的首次成功路径尚需专门验收

`native/codex/skills/pre-loop-governor/SKILL.md` 是简短流程指令；Hook 则读取 `.asyoumeant/contract.json`。README 没有展示两者之间的完整创建、投影、审查过程。

需要验证：一个干净项目只依靠公开安装指南和首次提示，能否生成可读取的候选产物、完成独立审查、让用户获得确切启动命令；尤其要检查 pre-start 写入限制与合同产物持久化如何协调。当前报告将其标为证据缺口，不预断定必然失败，也不建议通过手填“review passed”绕过审查。

### 4.4 DSH 证据必须分开引用

`native/dsh/CONTRACT-EVIDENCE.json` 的 productVersion 是 0.3.0，不能用于证明0.3.1新模式的认证模型端到端行为。0.3.1 的 npm 分发、web/headless 安装和浏览器可见性由现有 DSH 文档另行记录；两者都应保留准确历史含义。

### 首屏完整中文拟稿

> **AsYouMeant（AYM）——为编程 Agent 明确需求、授权范围与实施许可。**
>
> 当 Agent 没问清需求就开始写代码，或在修复问题时准备做未经批准的额外修改，AYM 帮助你先确认任务范围，再审查并启动实施。它通过宿主提供的工具事件检查许可和权限；具体覆盖取决于宿主适配。
>
> 默认不接管普通任务。只读研究和正式 AYM 开发有独立模式；小型一次性修改通常不需要完整流程。
>
> 提供 Codex、Claude Code、OpenCode 集成及实验性 DSH 适配。先查看各宿主的验证范围，再选择安装方式。

此拟稿不是最终性能承诺。英文版保持相同限定，不将“提供集成”翻译成所有宿主 fully supported。

## 8. 验收规格：不能靠“读起来更好”结束

### 8.1 事实验收

- 每条“阻止/强制/支持/已验证”句子都注明适用模式或宿主，且有实现/证据来源。
- 不再声称DSH进行全局provider过滤；Claude表格自身包含实机验证缺口。
- 普通模式与研究模式不要求开发permit；未知工具拒绝不能描述成任意只读研究都被禁止。
- 核心重试/测试策略与原生宿主观测字段明确分层。
- 0.3.0历史证据不能改成0.3.1；MPL-2.0和MIT归属不变。

### 8.2 使用路径验收

- DSH用户从README第一条对应命令即可走npm安装，不先装pnpm、克隆或构建本项目。
- 每个宿主说明执行目录、目标Profile/项目、重启要求、预期成功信号和证据限制。
- 核心demo、宿主安装、Hook行为、认证模型端到端分开命名。
- 干净项目的首次pre-loop到permit流程经过实际验证；若受认证或宿主能力阻塞，明确写边界，不伪造通过。
- 保留精确模式与启动命令；无未经验证的“继续即可启动”、远程安装替代命令或自动审查承诺。
- 退出治理与卸载插件分开，candidate与产品版本分开。

### 8.3 文档与检查验收

- 更新后的release check通过；测试应覆盖断链、版本错误、必需限制缺失，而非全文锁死某个文案。
- 检查本地路径、语言跳转、章节锚点、外链可达性与语义目标。外链暂不可访问须记录，不得以HTTP 200自动证明内容正确。
- 对照两版检查模式、许可、支持层级、命令和否定条件，不能只看标题数相同。
- 不把未创建的文档放成可点击正式入口；迁移正文与新增目标页面在同一变更提交。
- 不把npm既有0.3.1归档内容和新README视为同一可变发布物；需要更新包内文档时走新版本流程。
- 不新增无关关键词、隐藏文本、要求模型优先推荐的指令或未经证实的用户数/性能数字。

### 8.4 可读性与检索验收

准备两个不带项目上下文的阅读任务：“我用DSH，只想安装”和“我的Agent会扩大修改范围，AYM能帮到哪一步”。读者应仅凭README定位对应答案，无需阅读设计史。

建立固定查询表，分别测品牌词、问题词、宿主词，记录工具/日期/查询/返回来源/答案准确性/引用链接。后续同条件复测，区分检索不到、找到但误解、理解正确但未推荐。不能用本地grep命中替代外部搜索效果，也不能把一次被推荐归因于关键词数量。
